# 다음 작업

## 필수: 실제 실행 환경 확보

1. Android SDK API 36, Build Tools 36.0.0, JDK 17, Gradle 9.6.0 환경에서 Debug 빌드·설치. 최신 Android와 저사양 Android에서 촬영, 파일 선택/저장, 뒤로가기, 키보드, 인셋을 검증하고 오류 수정.
2. PC·모바일 브라우저에서 `evidence/UI_QA_CHECKLIST.csv`의 모든 항목을 직접 실행하고 화면·결과 증거를 남김. 320/360/390/768/1440px, 200% 확대/큰 글씨, 키보드·스크린리더, 중복 클릭·저장 실패·재실행·오프라인 포함.
3. 실제 IndexedDB에서 등록→수정→원본 포함 백업→복구→종료/재실행→삭제 검증. 저장 중 앱 종료, quota 부족, 여러 탭 동시 편집, 삭제가 blocked인 경우 복구 확인.
4. 실제 브라우저에서 일보·견적·계약 초안·사진 PDF를 출력해 한글, 긴 항목, 줄바꿈, 여러 페이지, 50장 사진, 파일 저장·공유를 확인. 현재 PDF 조립 fixture는 이 검증을 대신하지 않음.

## 필수: 클라우드 및 AI

5. 운영자가 승인한 현장AI365 전용 Firebase 프로젝트의 공개 설정값과 운영 조건 확정. 비용·Storage 요금제 변경과 실제 규칙 배포는 승인 후 진행.
6. Firebase Emulator 및 테스트 프로젝트에서 규칙 실행 검증. 미인증/다른 UID 읽기·목록·쓰기·삭제 거부, 삭제 잠금 후 다른 기기의 업로드 거부, 원본별 객체·CAS 충돌·고아 객체·실제 전체 계정 삭제 검증.
7. 두 기기의 동일 계정 동기화, 계정/프로젝트 전환, 토큰 만료, 업로드 후 단절, 재시도, 사진 백업 복원과 원본 변경 수신을 실제로 재현.
8. 선택한 모델·예산·HTTPS 서버 승인 후 실제 AI 연결. 개인정보 전송 범위, 서비스 오류, 시간 제한, 승인형 설정 적용 확인. 현재 시간당 한도는 프로세스 내 메모리 기반이므로 외부 운영 시 지속적 한도·예산 차단·관측 필요.

## 필수: 출시 전 남은 제품 작업

9. 사용자별 업무 빈도·업무 방식까지 묻는 단계형 AI 최초 설정으로 확장. 현재 최초 설정은 회사·업종·선택 업무 폼이며 실제 모델 문답 검증 전임.
10. 비밀번호 재설정·가입 이메일 확인, 삭제 실패의 진행 상태와 재시도 안내, 다른 기기의 삭제된 계정 데이터 정리, 공개 계정 삭제 요청 페이지, 운영자/보유기간/문의처를 갖춘 개인정보처리방침 구현·검증.
11. 주소 선택 연동과 Android 직접 음성/공유 경험 확정. 현재 주소는 수동 입력+외부 지도 검색, 음성은 지원 브라우저 기능, 공유는 저장한 파일을 통한 외부 공유임.
12. 서명 키 확정, Release APK/AAB 생성, 서명·설치·업데이트·회귀 검사. 앱 식별자와 스토어 권리 확인, 실제 화면 캡처, 설명·Data safety·테스트 트랙·심사 접근 경로 준비. 공개 출시 직전 최신 정책 재확인과 사용자 승인.

## 권장: 운영 규모에 따른 개선

- 수동 전체 목록 동기화를 변경분 동기화로 전환하고 실제 비용/성능 측정.
- 버전별 사진과 CAS 실패 고아 객체의 보존 기간·정리 작업. 자동 정리는 운영 중 중요 원본을 삭제하지 않도록 참조와 백업 상태 검증이 먼저 필요함.
- 사진이 많은 현장 목록의 페이지 처리, PDF 생성 진행/취소, 임시 입력 복구, 관리형 백업과 로컬 저장 보호.
- 래스터 PDF를 검색 가능한 한글 PDF로 개선.

## 선택 / 제외

선택: 지도 주소 API, 고급 음성 입력, 구독·청구. 비용·개인정보·가격은 승인 후 설계.

제외: 자동 세금계산서 발행, 무승인 법적 계약 체결·행정 제출, AI 생성 실행 코드 적용.

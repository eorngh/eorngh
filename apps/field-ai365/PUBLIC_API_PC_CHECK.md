# 기존 공공 주소 API 설정 점검

승인키를 이미 설정했지만 서버 실행 위치를 모를 때 사용하는 진단이다.
프로젝트의 `.env.local` 또는 현재 프로세스의 `JUSO_SEARCH_KEY`를 재사용한다.
PC 전체 디스크, 브라우저 저장소, 다른 앱의 비밀 파일은 검색하지 않는다.

## 가장 간단한 실행

현장365 프로젝트에서 `CHECK_PUBLIC_API.cmd`를 실행한다. 결과는
`.local/public-api-check.json`에 저장되며 승인키 값이나 원문 주소는 포함하지 않는다.
Node.js 22 이상이 필요하고 추가 npm 패키지는 필요 없다.

1. 설정된 PORT(없으면 3650)의 루프백 서버가 현장365인지 확인한다.
2. 이미 실행 중인 현장365가 키를 보유하면 공개 주소 검색을 한 번 실행한다.
3. 실행 중인 서버를 확인하지 못해도 프로젝트의 키가 있으면 임시 루프백 서버로
   한 번 조회한 뒤 종료한다. 기존 서버를 종료하거나 포트·설정·방화벽을 바꾸지 않는다.
4. 조회 확인은 `PASS`, 키·실행 위치·승인 상태 등을 확인하지 못하면 `NOT_VERIFIED`
   또는 구체적인 실패 상태로 기록한다. 키 존재만으로 성공으로 판단하지 않는다.

이미 알고 있는 HTTPS 서버가 있으면 다음 명령도 사용할 수 있다.

```sh
node tools/check-public-api.mjs --server https://YOUR_SERVER
```

서버 주소에 승인키, 비밀번호, 토큰, 쿼리 문자열을 넣지 않는다. 명시한 서버를
검증하지 못하면 다른 프로젝트로 자동 전환하지 않는다. 임시 검증 성공은
상시 실행·Android 연결·인터넷 공개 서버 배포를 의미하지 않는다.

## PC Codex 전달문

```text
기존 현장AI365 프로젝트에서 공공 주소 API의 기존 설정 위치와 실제 조회를 점검한다.
저장소 eorngh/eorngh의 PR #2 브랜치 codex/field-ai365-source-20261023을 기준으로 한다.
기존 작업 트리와 .env.local/.local/서명키를 보존하고, 미커밋 변경은 덮어쓰지 않는다.
필요한 경우 별도 체크아웃에서 진단 도구만 준비한다. 설치된 Node.js를 우선 사용한다.
현재 프로젝트의 환경변수와 .env.local에서 JUSO_SEARCH_KEY 존재 여부만 확인한다.
승인키 값·파일 원문·전체 환경변수는 출력하거나 채팅·GitHub에 올리지 않는다.
다른 프로젝트나 PC 전체 디스크에서 비밀 파일을 검색하지 않는다.
현장365 폴더에서 node tools/check-public-api.mjs를 실행한다.
별도 체크아웃을 사용했다면 원래 프로젝트의 보호된 설정을 임의 복사하지 말고,
진단 도구를 원래 프로젝트에서 실행할 수 있도록 변경분만 안전하게 적용한다.
기존 설정 파일이 다른 경로라면 비밀 값 공개 없이 그 프로젝트의 확인된 로더를 따른다.
실행 중인 다른 서버를 종료하거나 승인키를 재발급·덮어쓰기·운영 배포하지 않는다.
결과는 .local/public-api-check.json의 상태·기존 서버 주소·조회 건수·미해결 원인만 보고한다.
접근하지 못한 다른 서버에 설정이 없다고 단정하지 않는다.
```

이 전달문은 PC에서 실행할 작업 지시이며, Work에서 PC 작업을 자동 실행했다는
뜻은 아니다. 보고서가 `NOT_VERIFIED`이면 다른 위치에 키가 있다는 사용자의
확인을 부정하는 것이 아니라 현재 점검 범위에서 실연동을 입증하지 못했다는 뜻이다.

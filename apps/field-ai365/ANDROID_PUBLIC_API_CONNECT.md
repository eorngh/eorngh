# Android 공공 주소 검색 연결

PC 임시 서버의 조회 성공은 승인키 유효성에 대한 증거다. 휴대폰이 사용할 상시
HTTPS 서버가 준비됐다는 뜻은 아니다. `localhost`는 휴대폰 자신을 가리키므로
PC의 임시 주소를 Android 설정으로 복사하지 않는다.

## 연결 방식

Android → 검증된 현장365 HTTPS 서버 `/api/address` → 행정안전부 공식 주소 API.
승인키는 서버의 `JUSO_SEARCH_KEY`에만 둔다. APK·웹 파일·GitHub에 넣지 않는다.
별도 API 패키지나 유료 AI는 사용하지 않는다.

기존 HTTPS 호스팅이 있으면 먼저 재사용 가능 여부와 비용을 확인한다. 기존
서버의 현장365 Node 프로세스(기본 루프백 3650)에 TLS 프록시를 연결하고
`ALLOWED_ORIGINS`에 `https://appassets.androidplatform.net`을 유지한다.
다른 서비스의 Hosting target, Firebase 규칙, 도메인과 포트를 덮어쓰지 않는다.
이 문서와 도구는 서버를 자동 배포하거나 방화벽을 열지 않는다.

## 기존 서버를 확인한 뒤 실행

```sh
node tools/configure-public-api.mjs --server https://YOUR_EXISTING_FIELD_SERVER
npm test
npm run build
```

서버 URL에는 경로·쿼리·승인키·비밀번호를 넣지 않는다. 도구는 현장365 서버 식별,
키 설정 여부, Android 출처에 대한 CORS 응답, 실제 주소 조회를 검사한다.
성공한 경우에만 `.local/public-api-runtime.json`에 공개 서버 origin을 기록한다.
오류 응답 원문과 검색 주소·승인키는 출력하지 않는다. 실패 시 기존 설정을 보존한다.

빌드는 검증된 origin 한 필드만 Android 비공개 빌드 자산으로 복사한다.
설정 파일이 없으면 이전 빌드의 서버 설정을 제거하고 앱은 미연결을 안내한다.
연결 해제는 `.local/public-api-runtime.json` 삭제 후 재빌드로 수행한다.

## 실제 기기 합격 기준 (아직 미검증)

1. 기존 패키지·서명으로 업데이트 설치하고 현장 데이터 보존 확인.
2. PC 임시 서버를 종료한 상태에서 휴대폰 모바일 데이터로 주소 조회.
3. 도로명·지번·공식 출처·조회 시각을 선택·저장 후 재조회.
4. 비행기 모드·서버 장애 시 오류 안내와 주소 직접 입력 확인.
5. APK에 승인키가 들어가지 않았는지 확인.

상시 서버 주소를 확보하지 못하면 연결 완료로 표시하지 않고 다음 전달문으로
기존 PC 환경을 조사한다. 승인키를 다시 입력하거나 재발급할 필요가 없다.

```text
현장365 PR #2 최신 변경을 기존 소스·미커밋 변경·.env.local·서명키를 보존하며 반영해줘.
ANDROID_PUBLIC_API_CONNECT.md를 따라 기존 배포 설정에서 현장365가 사용할 수 있는
HTTPS 서버와 실행 프로세스를 찾아줘. 비밀 값·전체 환경변수는 출력하지 마.
검증된 기존 서버가 있으면 tools/configure-public-api.mjs --server 서버주소를 실행하고
테스트·빌드 후 기존 서명을 유지해 설치 후보를 만들어줘.
서버가 없다면 기존 Firebase/호스팅 설정에서 충돌 없는 배포안을 준비하고
대상·예상 추가 비용·변경사항을 보고해줘. 임의 유료 개설·공개 배포는 하지 마.
주소 조회 성공, Android CORS 검사, 빌드, 실제 기기 검증을 각각 구분해 보고해줘.
```

## 이번 변경의 확인 범위

2026-10-25: 연결 경로 및 설정 도구 구현. 합성 데이터 기반 계약·CORS·빌드 설정
검사를 추가했다. 기존 PC 조회 성공은 사용자가 제공한 화면에 근거한다.
상시 HTTPS 서버 주소·실제 Android 설치·모바일 데이터 조회는 아직 미검증이다.
운영 서버·Firebase 규칙·Play 배포 및 서명키는 변경하지 않았다.
